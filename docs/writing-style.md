# 教材の文章ガイド

章を追加・改訂するときはこのガイドに従う。10 章以降を書く人（人間・AI とも）が対象。

出典: 技術書出版社が公開している LLM 向け技術文書ルール、AI 生成文のリライト術の記事、
および Diátaxis のチュートリアル設計原則を、このリポジトリ向けに要約したもの。

## 書いてはいけないもの

- 本文中の予告と総括。「この章では〜を扱う」「まとめると」「重要なのは〜である」。
  読めば分かることを宣言しない。章末の「まとめ」節だけは例外で、
  核心 1 段落 +「次に何をすべきか」を書く（下の「章の構成」参照）。
- 空虚な修飾。「強力な」「シームレスな」「鍵となる」「根本的な」「非常に」「劇的に」。
  形容詞を消しても意味が変わらないなら、その形容詞は要らない。
- 箇条書き・表・太字の乱用。「考え・因果」は段落で、「列挙できる事実・仕様値・手順」は
  箇条書きで書く。どちらかに偏らせない。太字は 1 ファイルに数カ所まで。
- 長文の段落。1 段落は 2〜4 文まで。5 文を超えたら分割するか箇条書きに直す。
- 「〜しましょう」の連続。手順は命令形で書く（「実行する」「確認する」）。
- どの文も同じ長さ・同じ文末。です・ます が均一に並んだら書き直す。
- 網羅癖。「3 つのポイント」「4 つの特徴」のような、数を揃えるための列挙をしない。
  言うべきことが 2 つなら 2 つだけ書く。
- 読者が補えない省略。主語や指示語（「これ」「この値」「土台」）の指す先が文中に無い文、
  「生で叩く」「握りつぶす」のような口語・比喩だけの説明を書かない。
  比喩を使うなら、その実体（何をどうすることか）を同じ文か直後に一句添える。

## 書くべきもの

- 最初に到達点。章の冒頭で「終えると何ができるようになるか」を具体的に示す。
  抽象的な学習目標ではなく、「〜が動く」「〜を自分で説明できる」の形で。
- 実測値と実体験。このリポジトリには本物の数字がある
  （コールドスタート 4 秒、テスト 36 件、8080 番ポートを Docker Desktop に取られた話）。
  一般論の代わりにこれを使う。
- 因果のメカニズム。「A するとよい」ではなく「A しないと B が起きる。なぜなら C だから」。
- 期待される結果。手順の各ステップに「こうなるはずだ」を添える（Diátaxis）。
  読者は自分が正しい道にいるか、常に確認できる必要がある。
- 一本道。チュートリアル部分では選択肢を並べない。代替手段の議論は解説側に置くか消す。
- 一文だけの段落。長い説明のあとに短い一文を置くと、そこが読まれる。

## 章の構成

節の並びは全章で固定する。手本は `01-invoke-bedrock/README.md`。

1. 冒頭（見出しなし）— 到達点と、章のセットアップコマンド
2. `## N.1 概要` — その技術は何か・何を解決するか・全体の中の位置づけ。
   構造が伝わる場合は Mermaid 図を置く。仕様値は裏取り済みのものだけ書く
3. `## N.2 実装のポイント` — このリポジトリの実装・規約との対応。設計判断の理由はここ。
   内容が無い章（環境構築・通読の章）は省略してよい
4. `## N.x 【ハンズオン】...` — 手順
5. `## N.last まとめ` — 核心 1 段落。「結局これは何で、次に何をすべきか」
6. `## 次の章` — 次章へのリンク

- 見出しは `# 第N章 タイトル` → `## N.x 節` → `### N.x.y`
- 解説節（Diátaxis の explanation）とハンズオン節（tutorial）を同じ README に置くが混ぜない。
  解説は読み物、ハンズオンは命令形の手順 + コマンド
- コマンドはコピペしやすいよう 1 ブロック 1 実行単位。直後に「〜が出るはずです」と期待結果を書く
- 実行スクリプトは章ディレクトリ直下に `01_*.py` の連番で置く
- verify/: 合格条件のテスト表現。失敗メッセージには「README のどの節を読み直すべきか」を入れる
- ハンズオンは 2 方式。**写経方式**（タイプ A）は README がコードを段階提示し、章を独立した
  uv プロジェクトにする（pyproject.toml を持たせ、学習者は uv sync → 連番スクリプトを書く →
  `uv run 01_xxx.py`）。**要件実装方式**（タイプ B）は要件と判定テストだけ与え、
  コード全文は solutions/ にのみ置く。序盤は A、型を覚えた後は B
- どの章も「学習者がコードを書く」工程を必ず含める。読んで答えるだけの章を作らない

## 推敲チェック

書き終えたら次を確認する。

1. 冒頭 3 行だけ読んで、何ができるようになる章か分かるか
1. 仕様値・数値に裏取り（一次情報 or 実測）があるか。無いものは書かない
2. 箇条書きを 2 つ以上、段落に書き直せないか
3. 「重要」「ポイント」「しっかり」を検索して全部消せないか
4. 実測値・実例がひとつも無いセクションはないか
5. 音読して、文末が 3 連続で同じになっていないか
